# 400 m 실험 구역 데이터 파이프라인

기본 실행은 `run_five_maps.py`입니다. 저장된 실제 입력을 읽어 맵을 만드는 과정은 오프라인이며, 원본 자료 재수집과 분리됩니다. 지역·범위는 `config/regions.five.json`에서 고정합니다.

기본 5개 구역의 순서는 **강남역 → 테헤란로(포스코센터) → 홍대 → 분당 → 상암 DMC(누리꿈스퀘어)**입니다. 이전 여의도·판교 포함 설정은 별도 JSON으로 보존한 뒤 `run_five_maps.py --config <설정 경로>`로 재실행할 수 있습니다. 확정 세트와 이전 세트를 임의로 섞은 5개 키는 허용하지 않습니다.

## 1. 공식 건물 원본 → 지역 입력

[브이월드 GIS건물통합정보](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=18)의 **전체데이터 SHP ZIP**을 사용합니다.

| 범위 | 현재 배포본 | 대상 지역 |
|---|---|---|
| 서울특별시 | `AL_D010_11_20260909.zip` | 강남역·테헤란로·홍대·상암 DMC |
| 경기도 | `AL_D010_41_20260909.zip` | 분당 |

원본은 `data/raw/official_vworld/`에 보관하고 Git에서 제외합니다. CP949를 명시해 DBF를 읽고, `.prj`·GDAL CRS·배포 시점의 좌표계를 대조합니다. 현재 원본은 EPSG:5186이며 EPSG:5179로 변환합니다. CRS를 추정해서 강제로 붙이지 않습니다.

```powershell
# 입력 묶음이 없는 새로운 추출 작업에서 사용
.\.venv\Scripts\python.exe scripts/import_five_regions.py
```

스크립트는 기존 건물 출력 파일을 덮어쓰지 않습니다. 재추출 비교 시에는 별도 설정 파일의 `data_dir`을 새 프로젝트 내부 경로로 지정하고 `--config`를 사용합니다. 준비된 입력으로 실행하는 데 전체 ZIP은 필요하지 않습니다.

| AL_D010 열 | 의미 | 처리 |
|---|---|---|
| A1 | GIS건물통합식별번호 | 문자열 건물 식별자 |
| A2 | PNU | 필지 확인용; 건물 동일성 단독 근거로 사용하지 않음 |
| A16 | 높이(m) | 유한한 양수만 GIS 확인 높이로 채택 |
| A19 | 건축물ID | 원본 보존; 다른 대장 PK와 같다고 가정하지 않음 |
| A22 | 데이터기준일자 | 선택 레코드 기준일 보존 |
| A24 / A25 | 건물명 / 동명 | 동일 건물 검토 자료; 지도 이름표는 표시하지 않음 |
| A26 / A27 | 지상 / 지하 층수 | 동일 건물 검토 자료; 높이 환산에 사용하지 않음 |

지역과 교차하는 건물의 **전체 외곽선과 원본 높이값**을 보관합니다. 400 m 경계 절단, 추정 높이, 비행 제한 영역은 모델 단계에서 생성합니다. 배포 기준일은 2026-09-09, 선택 레코드의 A22는 2026-09-06입니다.

테헤란로·상암 DMC의 새 중심은 랜드마크 원본 폴리곤의 EPSG:5179 무게중심으로 고정했습니다. 정해진 400 m 정사각형과 **양의 면적**으로 교차하는 고유 A1 건물만 집계하고, A16의 유한한 양수 개수 비율이 **엄격히 60% 초과**인지 선정 단계에서 확인했습니다. 테헤란로 124/148(83.78%), 상암 DMC 26/38(68.42%)입니다. 이 선정 조건과 아래의 대장 완료·미확인 다수 보류 조건은 별개이며, 선정에 통과해도 대장 검토를 생략하지 않습니다.

설정의 지역별 `center_status`를 출력 manifest로 전달합니다. 이전 구역은 공유 대화 후보점, 새 두 구역은 GIS 랜드마크 폴리곤 무게중심으로 구분합니다. 상암은 건물 개수 기준 밀도가 낮은 큰 블록의 계획형 업무·미디어 지구로 설명합니다. 건물 외곽선 면적 점유율과 높이가 테헤란로보다 낮다는 뜻은 아닙니다.

## 2. 실제 OSM 배경

```powershell
# 기존 검증된 지역 배경은 재사용하고 없는 배경만 순차 수집
.\.venv\Scripts\python.exe scripts/fetch_five_backgrounds.py

# 네트워크 없이 저장 파일 검증
.\.venv\Scripts\python.exe scripts/fetch_five_backgrounds.py --offline
```

OSMnx `features_from_polygon`으로 `highway`, 공원·정원, `landuse`, 물·수로 태그를 수집합니다. OSM 건물은 사용하지 않습니다. EPSG:5179 변환 후 정확한 400 m 정사각형으로 자르고, 원본 OSM ID·이름·터널·layer 등 태그를 보존합니다.

Overpass 조회는 지역별 순차 실행이며 요청 시간 제한과 작업 전체 시간 제한을 둡니다. 지역·중심·태그·OSMnx 버전에 대응하는 캐시를 사용합니다. `--rebuild`는 저장 묶음을 다시 생성하되 같은 질의의 캐시가 있으면 재사용하므로, 반드시 최신 OSM을 받는 옵션은 아닙니다. 실제 DB 시점은 `osm_database_timestamps_utc`가 기준입니다.

도로는 원본 중심선이며 폭을 추정하지 않습니다. 요소 수는 잘라진 선·폴리곤 조각 수로, 도로 이름 수가 아닙니다. 특정 분류의 0개는 해당 질의에서 남은 형상이 없다는 뜻입니다.

## 3. 건축HUB 대장 조회와 동일 건물 검토

GIS 높이가 없는 건물은 건축HUB의 **개별 건물 대장**을 검토합니다. 현재 비교 대상은 2026년 8월 공개 조회 자료이며 GIS 9월 배포본과 기준 시점이 다릅니다. 대장 높이 필드 `HG`는 m 단위입니다. 총괄표제부나 여러 동을 합친 값은 개별 높이로 사용하지 않습니다.

전처리에서 필지 전체의 GIS 건물을 함께 확인해, 400 m 밖의 같은 필지 건물을 놓친 채 1:1 관계로 착각하지 않도록 합니다. 이 자료는 `ledger_identity_context.json`에 기록하며, 그 파일 자체가 건물 연결을 승인하는 것은 아닙니다.

채택하려면 검토 근거가 있는 개별 건물 1:1 연결이 필요합니다. 주소 유사성·필지·단지 이름만으로 연결하거나 하나의 대장 높이를 여러 동에 복제하지 않습니다. 채택값은 GIS가 결측일 때만 보완합니다.

| 파일 | 역할 |
|---|---|
| `ledger.csv` | `namespace,ledger_id,record_type,height_m`; 개별 건물 기록은 `record_type=title` |
| `verified_matches.csv` | `building_id,ledger_id,namespace,verified,identity_method,identity_evidence` |
| `ledger_audit.json` | 건물별 조회·식별 검토 상태, 사용 자료와 근거 |

`verified=true`, `identity_method=official_crosswalk` 또는 `manual_building_confirmation`, 비어 있지 않은 확인 근거를 요구합니다. 건물 및 표제부 식별자의 중복·일대다 연결은 거부합니다. CSV 두 개는 쌍으로 제공하며, 파일 해시를 출력 manifest에 남깁니다.

대장 자료에서 찾지 못함·높이 결측·동일성 불명확 같은 **검토 결과**와 네트워크 오류·인증 실패·미조회 같은 **검토 미완료**를 구분합니다. 검토 미완료를 추정 허가로 처리하지 않습니다.

확정 구역 중 새 테헤란로·상암 DMC에는 대치동 2,456행, 삼성동 2,402행, 상암동 1,065행으로 **3개 법정동 표제부 5,923행**을 추가 조회했습니다. 테헤란로의 GIS 결측 24개와 상암 DMC의 12개를 검토했고, 채택 가능한 추가 높이는 0개였습니다. 두 지역의 검토 결과 합계는 `title_height_missing` 12개, `no_title_found` 12개, `identity_ambiguous` 10개, `identity_unconfirmed` 2개입니다. 이 36개는 대장 검토가 완료된 뒤에만 실험용 추정 높이로 처리했습니다.

2026-10-07의 **초기 5개 구역(강남역·여의도·홍대·판교·분당)** 검토에서는 8개 법정동의 표제부 15,897행을 확보했습니다. 각 JSON 행 수는 공식 조회 화면의 전체 건수와 대조했습니다. 해당 구역의 GIS 높이 결측 305개를 모두 검토했으며, 엄격한 동일 건물 조건을 통과해 새 높이를 채택한 건물은 0개입니다. 아래 표는 이 초기 조합에 한정한 이력이며, 새 테헤란로·상암 DMC 검토 통계를 대신하지 않습니다.

| 대장 검토 결과 | 건물 수 | 해석 |
|---|---:|---|
| `title_height_missing` | 107 | 검토한 개별 대장 또는 후보의 `HG`에 유효한 양수 높이가 없어 보완하지 못함 |
| `identity_ambiguous` | 137 | 후보 또는 필지 내 건물 관계가 모호하여 하나의 동일 건물로 확정하지 않음 |
| `no_title_found` | 56 | 확보한 조회 자료에서 정확한 PNU의 대장 후보를 찾지 못함 |
| `identity_unconfirmed` | 5 | 후보는 있으나 동일 건물 확인 근거가 부족함 |

이 결과는 모든 건축물대장에 높이가 없다는 뜻이 아닙니다. 특히 후보가 모호한 건물에는 높이가 기록된 후보가 있어도 채택하지 않습니다. 2026년 8월 대장 조회 자료와 9월 GIS 배포본 사이의 시점 차이도 기록합니다. 전체 수집 근거는 로컬 `data/raw/building_hub/acquisition.json`, 배포 가능한 지역별 결과와 원본 해시는 각 `ledger_audit.json`에 있습니다.

## 4. 모델 준비 상태와 높이 정책

| 상태 | 조건 | 결과 |
|---|---|---|
| `pending_ledger` | GIS 결측 건물에 대한 대장 확인 미완료 | 상태 페이지·manifest·quality만 생성 |
| `held` | 검토 완료 후 미확인 수 > 확인 수, 또는 확인 높이가 0개 | 같은 보류 결과만 생성 |
| `ready` | 확인 절차 완료, 확인 높이가 있으며 미확인 수 ≤ 확인 수 | 남은 결측에 실험값 적용 후 모델 생성 |

현재 확정 구역의 상태는 실행 시 생성되는 `suite.manifest.json`과 지역별 `manifest.json`에서 읽습니다. 입력 자료 검증과 대장 확인 게이트를 통과한 구역만 `ready` 모델을 만듭니다.

확정 실행 `five_actual400_20261007_confirmed`에서는 **5개 모두 `ready`**입니다. 확인 높이는 모두 원본 GIS이며 대장 추가 높이는 0개입니다.

| 지역 | 전체 | GIS 확인 높이 | 적용한 추정 높이 | 미처리 결측 | 상태 |
|---|---:|---:|---:|---:|---|
| 강남역 | 100 | 63 | 37 | 0 | `ready` |
| 테헤란로 | 148 | 124 | 24 | 0 | `ready` |
| 홍대 | 513 | 341 | 172 | 0 | `ready` |
| 분당 | 60 | 45 | 15 | 0 | `ready` |
| 상암 DMC | 38 | 26 | 12 | 0 | `ready` |
| 합계 | 859 | 599 | 260 | 0 | 5개 생성 |

참고로 **초기 조합의 과거 출력**(`five_actual400_20261007_142609_973334`)은 다음과 같습니다. 확인 높이는 모두 원본 GIS이며 대장 추가 높이는 0개였습니다.

| 지역 | 전체 | 확인 높이 | 적용한 추정 높이 | 미처리 결측 | 상태 |
|---|---:|---:|---:|---:|---|
| 강남역 | 100 | 63 | 37 | 0 | `ready` |
| 여의도 | 51 | 15 | 0 | 36 | `held` |
| 홍대 | 513 | 341 | 172 | 0 | `ready` |
| 판교 | 66 | 21 | 0 | 45 | `held` |
| 분당 | 60 | 45 | 15 | 0 | `ready` |

이 초기 실행에서 강남역·홍대·분당의 추정값 224개는 확인 높이에 포함하지 않았습니다. 여의도·판교의 결측 81개에는 추정값을 넣지 않았으며 3D 모델을 생성하지 않았습니다. 해당 원본·검토 기록을 보존하면서 현재 기본 실행 대상만 확정 구역으로 변경했습니다.

확인 높이의 평균 `μ`를 구하고, 남은 건물에 ±5 m 안의 균형 잡힌 편차를 배정합니다. 편차 합은 0이고 추정 높이의 평균도 `μ`입니다. 정렬된 건물 ID와 기록된 지역별 난수 시드로 재현합니다. 홀수 개이면 한 건물은 `μ`가 됩니다. 양수 높이를 보장해야 할 때는 편차 폭을 줄입니다.

`height_m`은 모델 적용 높이이며 `height_source`는 `gis`, `ledger`, `imputed`, `missing`을 구분합니다. 추정 건물의 `observed_height_m`은 null, 원본 결측은 `height_source_original`과 `gis_height_raw`에 남습니다. `imputation_delta_m`과 `ledger_check_status`로 적용 사유를 추적합니다.

## 5. 비행 제한 영역과 결과 연결

50 m 이상 건물의 전체 원본 외곽선에 수평 안전 여유(기본 5 m)를 적용한 뒤 연구 영역으로 자릅니다. 확인 높이 기반과 추정 높이 기반을 분리해 기록합니다. 원래 건물 메시를 확장하거나 높이를 변경하지 않습니다.

확정 실행의 건물별 제한 영역은 강남역 67개(확인 30·추정 37), 테헤란로 25개(확인 25), 홍대 0개, 분당 13개(확인 13), 상암 DMC 32개(확인 20·추정 12)입니다. 중첩 영역을 합쳐 세는 값이 아니라 조건을 충족한 건물별 폴리곤 수입니다.

- `no_fly.local.json`: 중심 원점의 m 단위 영역. `flight_policy`와 각 영역의 `is_estimated`를 함께 읽습니다.
- `scene.local.json`: 같은 좌표 기준의 건물과 비행 제한 영역.
- `buildings_known_heights.obj`: 확인 높이 건물만 포함. 모든 장애물이 있는 완전 장면으로 해석하지 않습니다.
- `buildings_model_heights.obj`: 명시적으로 표시한 추정 높이를 포함한 실험 장면.

경로 계획 코드는 이 영역으로 위치·선분 침범을 검사하고, 통신 코드는 원래 건물 폴리곤과 적용 높이로 LoS/NLoS 등을 계산하도록 연결할 수 있습니다. 현재 단계에서는 해당 전파 계산과 드론 이동 실행을 수행하지 않습니다.

## 저장·배포 범위

공유하는 지역 묶음에는 실제 추출 GIS·OSM, 필요한 대장 기록과 확인 근거, schema, 출처·체크섬·이용조건을 포함합니다. 서울·경기 전체 ZIP과 건축HUB 전체 원본은 `data/raw/`, 네트워크 캐시는 `.cache/`, 생성 장면은 `outputs/`에 두며 Git에서 제외합니다. 인증정보와 기기 절대 경로는 출처 기록에 넣지 않습니다.

지역별 `LICENSE-BUILDINGS.md`, `LICENSE-OSM.md`와 제공 자료의 출처 조건을 함께 유지합니다. 코드·지도 출력·원본 데이터의 이용조건은 서로 구분합니다. SHA256 검증은 사용 파일의 일치를 확인하는 절차입니다.
